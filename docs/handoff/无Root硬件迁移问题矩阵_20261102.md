# K90 Max ColorOS 17 无 Root 硬件迁移问题矩阵

## 基线

- 基线镜像：Stage14（交付目录名仍为 Stage13_COMBINED）。
- 2026-11-02 已关闭全部 KernelSU/LSPosed/性能/快充模块并重启成功。
- 误装的 `k90max_powerhal_uclamp` 已卸载，最终方案禁止依赖 Root 模块。
- 底层 vendor/odm 身份保持 Redmi `prague`；不得替换 modem、NV、persist、TEE 等关键分区。

## 分阶段原则

1. Stage16A：只做已能用实机证据闭环的 SELinux/属性访问修复，先保证启动可回退。
2. Stage16B：实现并内置 charger bridge，必须在 `sys.boot_completed=1` 后启动，失败不得拖垮 system_server 或 HAL。
3. Stage16C：GPU/性能接口映射，保留 Xiaomi 温控与 DVFS，不锁最高频率。
4. Stage16D：指纹 UI 与人脸重录的 framework/SystemUI 原生适配。
5. Stage16E：双卡/飞行模式/运营商显示实机矩阵，保持 Prague modem/NV 身份。

每阶段至少完成两次冷启动、一次充电启动，并保留上一阶段可刷回的 `super.img` 与哈希。
