K90 Max 游戏音频与系统桥 v1.5.1

适用设备：Redmi K90 Max，代号 prague，平台 MT6993。

本版新增：
0. 启动时不把 SettingsProvider 的失败文本保存成“原值”；设置服务确实可用后才建立备份，并且只接受数字或 null。旧版留下的坏备份会被自动清理，避免退出游戏后把亮度等设置写坏。
0. 性能桥启动前检查真实文件，记录 PID 并在“操作”页确认进程仍然存活；不再仅凭一个 running 状态文件声称桥正常。
1. 游戏前台通过 Xiaomi TouchFeature 将触控上报档位切到 240；退出游戏、熄屏、过热降级或服务停止时立即恢复日常 135，避免日常额外耗电。
2. 增加 game/daily/thermal 三态策略：ColorOS 的 OplusPerfService 继续处理界面策略，小米 mi_thermald/MTK 后端执行真实场景；45C 进入过热回退，降到 41C 后才允许再次提升。
3. 修复退出游戏后 game_speed_up_switch 未恢复的问题，避免日常持续高功耗。
4. 游戏显示改用实机 ActiveMode 可达的 120Hz；165/144 虽被枚举，但当前 ColorOS 策略会夹到 120Hz，因此不再写入无效的 165。
5. 启用 ColorOS 原生晕动舒缓显示，并保留真实加速度计、陀螺仪链路。
6. 保持指纹快启相关系统开关，卸载模块时恢复安装前设置。
7. 修正快充认证判断的脚本优先级问题。
8. 增强前台应用识别，并在“操作”页显示晕动舒缓、指纹快启和定位状态。

验证边界：
- 触控模式 1011 的 240 和 135 均已由本机 Xiaomi TouchFeature 接收，并在内核日志中返回 SCP-THP success；模块未使用未验证的 360/480 档位。
- 当前性能日志已确认 UAH 请求进入 K90Urcc，并由 MTK PowerHal 实际下发三簇 CPU 频率、核心数和触摸 boost；模块不叠加长期锁频。
- 165Hz 首选物理模式请求实测仍回读 ActiveMode 120Hz，模块不会把设置值误报成实际刷新率。
- 参考的“定制温控 v6.2”会用闭源工具覆盖 /data/vendor/thermal/config 并重启 mi_thermald；本模块不复制其未审计的温控表，也不提供关闭保护的危险档。
- 参考的“振动设置 v1.75”会覆盖特定 809ab/9593 马达波形，本机采用 AW Awinic 170Hz 路径，故不复制其波形固件。
- 参考的 MusicHaptic v0.9.6 是音乐转 RichTap 触感，不是音质增强，本模块不把它伪装成 Bose 或音质功能。
- 晕动舒缓已在当前系统日志中确认创建 AntiDizzy 视图。
- 指纹识别本身正常，但小米指纹 HAL 的触摸按住事件尚未完整映射到 ColorOS。
  如果识别成功后仍不显示快启菜单，需要后续修复框架事件映射，不能靠伪造触摸安全解决。
- 当前系统已把指纹注册为强生物识别，微信和支付宝也拥有生物识别权限；但现场没有出现
  加密指纹认证成功计数。支付软件的环境判断、FIDO 或 Keystore 错误需要在复现时单独取证。
  本模块不绕过支付应用安全判断，不复制或伪造 TEE、StrongBox、密钥和认证结果。
- 当前 GNSS 和网络定位服务均在线，但日志存在网络定位时间戳倒退，且最近一次卫星定位误差较大。
  本模块不会覆盖设备校准、AGPS 配置或伪造坐标。
- 不移除温控，不写 modem、persist、nvdata、nvcfg、protect、preloader 等敏感分区。
- 模块不向 /data/local/tmp 或 /sdcard 写入临时文件，运行状态只保存在模块自身目录。

安装方法：在 KernelSU 管理器中选择本 ZIP，安装完成后重启。
管理器中的“操作”按钮可查看当前状态和最近日志。
